# flauz-orch

The execution graph for Flauz (F2 Wave 3, work order **ORCH-004**):
attributed multi-agent orchestration — a graph of agents, never a chat
relay.

One task may hold several agents cooperating with roles, dependencies
and blocked states: Agent A (research, browser) + Agent B (analysis,
terminal) + Agent C (independent review) running in parallel where B
waits on A's artifact and C verifies both. This crate owns the pure
data + evaluator of that graph.

## Semantics

- **Agent assignments.** An [`AgentAssignment`] carries who (an actor
  reference in the frozen grammar), a role label, the node's inputs
  (artifact-wait / resource-wait edges), its state
  (`ready|running|blocked|done|failed|verified`), and — for a verifier
  node — the independence scope. Harness states ride as plain opaque
  strings (the ORCH-003 seam).
- **No chat relay (structurally).** Agent-to-agent coordination happens
  through shared task state + artifacts/evidence. The dependency
  grammar (`WaitOn`) has exactly two kinds — `artifact_ready` and
  `resource_ready` — and the serialized grammar rejects every other
  kind on read, so a context-snapshot or transcript edge cannot even be
  expressed.
- **The independence rule (structurally).** A verifier node's inputs
  are the ARTIFACTS it verifies: graph validation requires a verifier
  to wait on at least one artifact from every node in its scope and
  forbids self-verification. Independence is structural, not
  behavioral.
- **The evaluator.** `ExecutionGraph::advance(graph, events)` is a pure
  deterministic function: it unblocks nodes when their waits clear
  (a blocked node always names what it waits for), attributes every
  produced artifact/evidence to exactly one node, derives the
  independently-verified overlay (done ∧ a finished verifier in scope →
  verified), fires the merge point when every node reaches
  terminal-success (all-done → the `task.verification_merged`
  descriptor, distinguishing verified from merely done — J-09's law at
  the task level), and records cancellation (non-terminal nodes fail;
  settled work and attribution are kept; the six-state vocabulary gains
  no `canceled` variant — the cancellation record distinguishes).
- **Honesty on every event.** Illegal transitions are errors, never
  silently accepted: producing while not running, producing the same
  artifact twice, starting a non-ready node, finishing a non-running
  node, failing a terminal node, canceling twice.
- **Task identity discipline.** The graph belongs to one task; the
  evaluator never rewrites the task reference. Run-again from a saved
  workflow seeds a NEW task and a NEW graph — never a fork.

## Inputs only — the frozen formats cross the seam

The crate does NOT import `flauz-world`, `flauz-exec`, `flauz-context`
or `flauz-cap` (the flauz-cap pattern): foreign entities cross the seam
exclusively as frozen format strings. `refs` re-validates the frozen
canonical-ID grammar (`<kind>_<ULID>`, Crockford Base32) for `task`,
`art`, `evd` and `res`, plus the frozen actor-reference grammar —
byte-identical in meaning to `flauz-world`'s types on the wire. Events
arrive as plain data; no runtime, harness or model is ever called.

## Canonical JSON (kernel §4)

Every top-level serialized contract type carries `"v": 1`, uses
snake_case field names, rejects unknown fields (`deny_unknown_fields`),
contains no floats, and tags enums internally with `"kind"`. Fixtures
live under `tests/fixtures/w3/` (typical / minimal / invalid per family:
agent-assignment, execution-graph, graph-event-sequence,
graph-evaluation) — generated by the evaluator over the documented fake
inputs, never hand-staged.

## Determinism (kernel §7)

No wall-clock reads, no randomness, no generated identifiers:
identical `(graph, events)` inputs produce byte-identical evaluations.
The public fakes (`fakes::fake_research_analysis_review_run` — the
deterministic 3-node research/analysis/review graph + its full
happy-path sequence; `fakes::fake_blocked_resolution_run` — the
blocked-resolution case) are the reference semantics for real graph
inputs.

## Credentials

None, ever: the graph holds references only, and the conformance test
`no_credential_material_in_serialized_state` scans every serialized
fixture and fake output.
