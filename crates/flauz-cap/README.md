# flauz-cap

The capability resolver for Flauz (F2 Wave 2, work order **CAP-001**):
intersection with named gaps — no silent fall-through.

A capability is available for a task iff **every** admission dimension
admits it (the frozen Wave-2 kernel addendum §4):

```text
model ∩ runtime ∩ environment ∩ permissions ∩ workspace policy
```

This crate computes that intersection over inputs taken as **data** and
produces the resolution record every gap surface builds on:
`CapabilityResolution` — the requested capability, the per-dimension
admission (each dimension either admitted or carrying its **named gap**
with an honest reason), and the unlock paths (per missing dimension, an
honest action hint that never promises an unlock the product cannot
perform).

## Semantics

- **Intersection with named gaps.** `resolve_capability` walks the five
  admission dimensions in canonical order (`Dimension::ALL`); a
  capability is available iff all five admit it. Every missing dimension
  is NAMED in the record (`NamedGap`) with its honest reason and mirrored
  one-for-one by an `UnlockPath`.
- **No silent fall-through.** A requested-but-missing capability always
  yields a NON-EMPTY gap list — a capability quietly missing from the
  offered set is a contract violation. The property test
  `no_silent_fall_through_every_missing_capability_names_its_gaps` proves
  it by deterministic exhaustive enumeration over the complete fake
  input space (`fakes::fake_input_space`, 144 cases).
- **Inputs only.** The resolver takes the model's capability metadata,
  the runtime advertisement, the environment surfaces, and the
  permission + policy decisions as call-side data. This crate does NOT
  import `flauz-world`, `flauz-exec` or `flauz-context`: foreign
  references cross the seam exclusively as frozen format strings —
  `CapabilityKey` re-validates the frozen namespaced-key grammar
  `[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)*` that `flauz-exec`'s
  `CapabilityId` owns. There is no permission system and no policy engine
  here: `PermissionDecision` and `PolicyDecision` are inputs.
- **Environment honesty.** "No environment attached" is a different named
  gap from "an environment is attached but does not offer the surface",
  and the two carry different honest unlock paths.
- **Determinism.** The resolver is a pure function of its inputs: no
  wall-clock reads, no randomness, no generated identifiers. Identical
  inputs produce byte-identical records.

## Canonical JSON (kernel §4)

Every top-level serialized contract type carries `"v": 1`, uses
snake_case field names, rejects unknown fields (`deny_unknown_fields`),
contains no floats, and tags enums internally with `"kind"` (fieldless
enums serialize as their lowercase names). Records carry no timestamps
or IDs. Fixtures live under `tests/fixtures/w2/` (typical / minimal /
invalid per record type, generated by the resolver over the documented
fake inputs).
