# flauz-lab

The provider-neutral parity-lab fabric for Flauz (F2 Wave 4, work order
**LAB-001**): declarative journey specs, the normalized evidence schema,
the named-findings registry, the reference-vs-candidate comparator, and
the lab-adapter contract with the local + fake-remote providers.

The lab's user is the **operator** (the Tech Lead; provider teams later).
A journey is defined once as data and runs unchanged against every
compliant lab adapter; evidence comes back normalized (schema'd,
canonical-JSON, comparable); the comparator diffs a candidate against a
reference with named divergences; and the F1 accessibility lessons ride
the schema as a named-findings registry that every future run references
by id.

## The F8 gate law — provider neutrality by construction

```text
JourneySpec (data) ──► LabAdapter (local | fake-remote | …) ──► EvidenceRecord (normalized)
                                    │                                        │
                                    └── comparator(reference, candidate) ◄────┘
```

- **`LocalLabAdapter`** — the in-repo reference-implementation driver:
  the contract plus a deterministic fake (`FakeAppSurface`) standing in
  for the operator's script-driven local lab. The local Linux lab is the
  reference provider.
- **`FakeRemoteLabAdapter`** — the CONSISTENCY provider (the ENV-001 law:
  the fake remote every later real remote copies): the same driver, the
  same deterministic surface, remote topology metadata (no `desktop.gui`
  — the honest named gap) and a provider-local digest namespace.
- **`FamilySkeletonAdapter`** — the real-provider families
  (E2B/Daytona/Azure/GitHub Actions/Codemagic) as adapter-family DATA
  with topology metadata, honest named-gap checks on `prepare`, and
  not-wired refusals on real work. No network; real integrations follow
  the lab-proven contract.

The test `the_same_journey_bytes_produce_comparable_evidence_from_both_adapters`
proves the law in-tests: the same journey bytes, two adapters, comparable
normalized evidence (the comparator reports zero divergences between the
local and fake-remote runs).

## Normalized evidence — frames are references, never pixels

An evidence record carries per-step action traces, frame REFERENCES with
their normalized anchor observations (the comparable content — not the
pixels), assertion results carrying the F1 patterns as data
(`FocusOn`/`FocusConfined`/`TextLanded`/`AnchorState`) with
known-findings links by id, VLM-read slots (the adjudication prompt + the
archived read-result reference — no VLM calls inside this crate), and the
environment/provider metadata (topology data, no credentials). The
comparator never compares provider-local fields: frame references,
digests (renderer fingerprints), VLM read references and adapter
descriptors are ignored by design.

## The named-findings registry

The five F1 accessibility lessons the work order names — PTY focus
transfer, bracket swap, modal focus traps, first-run keyboard swallowing,
the N6 shifted-symbol family — ride the schema as DATA
(`builtin_findings_registry`): id, surface, description, regression-guard
status. Records reference findings by id, never by prose; the
conformance tests prove every committed evidence link resolves.

## The comparator

`compare(journey, reference, candidate)` walks the journey against both
records and produces a canonical diff report: per journey step,
matching / divergent / missing evidence; per divergence, a NAMED kind
(`frame_anchors`, `assertion_verdict`, `assertion_observed`,
`assertion_findings`, `action_outcome`, `probe_missing`, `step_missing`,
`probe_shape`, `vlm_prompt`), a severity (`missing` > `major` > `minor`)
and a location (step + probe). Identical runs report ZERO divergences; a
seeded divergence comes out named, severe and located. Deterministic:
identical inputs produce byte-identical reports.

## Canonical JSON (kernel §4)

Every top-level serialized contract type carries `"v": 1`, uses
snake_case field names, rejects unknown fields (`deny_unknown_fields`),
contains no floats, and tags enums internally with `"kind"` (fieldless
enums serialize as their lowercase snake_case names). Timestamps do not
occur in v1 records: runs are ordered by the journey's own step order and
the crate never reads wall-clock time. Fixtures live under
`tests/fixtures/w4/` (typical / minimal / invalid per record family,
generated by the adapters over the documented fake journeys).

## Inputs only — the frozen formats cross the seam (the flauz-cap law)

This crate imports no contract crate: foreign entities cross the seam
exclusively as frozen format strings. The capability-key grammar is
re-validated locally (owned by `flauz-exec`'s `CapabilityId`), and the
adapter trait is NEW surface owned by this crate — not an
`ExecutionProvider` extension.
