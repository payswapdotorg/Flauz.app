## Provenance labels (mandatory)

The official Codex GUI is a **closed-source Electron application** (owl /
Chromium runtime) shipped for Windows and macOS at baseline; it cannot be
built or run in this laboratory (no Windows/macOS host; upstream
`openai/codex` contains no desktop crate — verified by repository listing in
Task 41). Therefore **every official-GUI claim below carries exactly one
label**:

| Label | Meaning |
| --- | --- |
| `[historical-record]` | In-repo captured records of the 26.721.3996.0 era: `docs/parity-matrix.md`, `docs/architecture.md`, `docs/platform-support.md`, `docs/known-failures.md`, `docs/prior-art.md`, `reference/stable-26.721.3996.0/manifest.json`, `docs/codex-universal/**`, CHANGELOG. ## User journeys (official-side expected flows)

### J1 — Coding (open project → task → edit → commit)

1. Launch app → `New chat` (or sidebar project → New chat) → `Open folder`
   Ctrl/Cmd+O → native `Select Project Root` picker → project remembered;
   next chat carries explicit `cwd`. `[historical-record]`
2. Describe the task; agent streams a timeline of `Explored`/`Ran` summaries
   with expandable command/diff/source rows; approvals arrive as native cards
   (Enter approve / Escape decline). `[historical-record]`
3. Open Terminal (bottom/right dock, PTY/ConPTY tabs) to inspect or run;
   background terminal activity appears as a completed-turn summary; Process
   Manager (Ctrl+Alt+M) lists/terminates background terminals. `[historical-record]`
4. Agent edits files; file-change items + `::output` citations appear;
   `Last Turn` in the Changes inspector shows the turn's patch; open a file
   from the Files preview or Sources. `[historical-record]`
5. Review diffs (Unified/Split; `Uncommitted`/`Unstaged`/`Staged` scopes),
   stage (`Stage all`), open the Commit dialog (`Include unstaged changes`,
   optional generated message), then `Commit` / `Commit and push` / `Push`.
   `[historical-record]`
6. Multi-repo projects (26.727+): `Review` inspects diffs across all
   repositories in the project. `[docs-derived]`

### J2 — Browser-assisted coding

1. The browser context starts before each interactive turn (agent can
   discover it even with the panel closed). `[historical-record]`
2. `Open browser tab` Ctrl/Cmd+T / `Toggle browser panel` Ctrl/Cmd+Shift+B;
   navigate via address bar (26.727+: history revisit + Google fallback);
   back/forward/reload/copy-URL shortcuts. `[historical-record]` + `[docs-derived]`
3. Origin/file-transfer/raw-CDP permission cards as needed (`Allow once` /
   `Allow for this site` / `Allow for all sites`; `Allow once` /
   `Allow this conversation` / `Always allow`). `[historical-record]`
4. Agent downloads are deny-by-default (10-second URL grant); user downloads
   prompt Save As; manage in the Downloads manager (Pause/Resume/Cancel/
   Open/Show in folder). `[historical-record]`
5. 26.825: site tools (WebMCP) let the agent use tools provided by a website
   in the built-in browser (GPT-5.6 Sol/Terra, non-Enterprise/Edu).
   `[docs-derived]`

### J3 — Planning (Plan → execution → Goal → result → continue)

1. `/plan` toggles plan mode; the agent proposes a multi-step plan.
   `[historical-record]`
2. Refine, then `/goal` sets the persistent goal (goal editor; file-backed
   attachments allowed). `[historical-record]`
3. Progress row above the composer shows the active goal with pause/resume/
   edit/clear; keep steering with follow-ups; Stop pauses the goal before
   interrupting. `[historical-record]`
4. Result attributed to the final response; context usage visible in
   `/status`; `/compact` when the context fills. `[historical-record]`

### J4 — Git workflow (branch → worktree → change → diff → review → commit)

1. Repository snapshot shows branch, ahead/behind, changed files, branches,
   worktrees, unique commits; create-and-checkout a branch (no force, no
   implicit stash). `[historical-record]`
2. Composer `Continue in` → `New worktree` (or `/fork` → `Continue in new
   worktree`): managed fork allocates a detached worktree under the Worktree
   root, reproduces working state, `thread/fork` with the new `cwd`;
   activity: `Creating a worktree` → `Worktree created` → `Starting the
   conversation`. `[historical-record]`
3. Make changes; `Uncommitted`/`Unstaged`/`Staged` diffs with +/− counts;
   stage/unstage; `Branch` source diffs current→remote-base. `[historical-record]`
4. `review/start` (`UncommittedChanges` or `BaseBranch`; Inline or Detached
   delivery); address findings; commit (and push). `[historical-record]`
5. Create PR (420 px flow with gh preflight, draft/ready, commit-and-push);
   review/merge from `/pull-requests` (Summary/Timeline/Checks/Code;
   approve/comment/request-changes; merge/squash). `[historical-record]`

### J5 — Recovery (interrupt → disconnect → reconnect → resume)

1. Stop button / Escape interrupts the active turn (`turn/interrupt`);
   approvals and user-input cards recover after reconnecting. `[historical-record]`
2. App-server exit → deduplicated 1/2/4/8/16/20 s reconnect timer; footer
   shows pending/running attempt state; initial failure is retryable.
   `[historical-record]`
3. After reconnect, `thread/loaded/list` rehydrates loaded/background
   sessions incl. active-turn state and subscriptions; drafts preserved
   (runtime 0.153 behavior). `[historical-record]` + `[docs-derived]`
4. Resume any past chat from the sidebar/history (`thread/resume`); archived
   chats unarchive on demand. `[historical-record]`

### J6 — Extensibility (MCP/Skill/Plugin → approval → execution → result)

1. Add an MCP server (STDIO or Streamable HTTP) in Manage MCPs; OAuth via
   `mcpServer/oauth/login`; status/tools/resources inspectable; `/mcp` shows
   connection state. `[historical-record]`
2. Install a plugin from a marketplace (Featured/categories; policy
   interstitial; `Try now`/`Manage`/`Uninstall`); connect Apps
   (`appsNeedingAuth` → `Connect apps to finish setup`). `[historical-record]`
3. Enable skills; invoke explicitly with `$` (current) or via slash rows /
   `@` mentions (baseline + current). `[historical-record]` + `[docs-derived]`
4. Tool invocations surface as timeline activity with approvals; MCP
   elicitations (URL / form / image-picker) render as native interruption
   cards with typed responses. `[historical-record]`
5. 26.727-era (post-baseline): Record & Replay — demonstrate a workflow
   once and turn it into a reusable skill (Computer Use enabled).
   `[docs-derived]`
